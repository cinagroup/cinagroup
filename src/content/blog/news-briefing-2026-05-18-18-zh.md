## 今日七大新闻

### 1. Anthropic 发布 Project Glasswing 与 Claude Mythos Preview——AI 模型在各主流操作系统和浏览器中发现漏洞

Anthropic 推出了 **Project Glasswing**——一项宏大的网络安全计划，将这家 AI 实验室与一个前所未有的科技巨头联盟结为伙伴，成员包括 Nvidia、Apple、Google、Amazon Web Services、Microsoft、摩根大通、博通、思科、CrowdStrike、Linux 基金会和 Palo Alto Networks。发布的核心是 **Claude Mythos Preview**——一个新的通用 AI 模型，Anthropic 出于安全顾虑刻意暂不向公众发布。

据 Anthropic 前沿红队网络负责人 Newton Cheng 称，Mythos Preview 已经标记出"数千个高危漏洞，其中包括每一个主流操作系统和网页浏览器中的漏洞"。该模型完全自主地取得了这些成果——"在没有任何人类引导的情况下"识别漏洞并开发相关利用代码。虽然 Mythos Preview 并非专为网络安全训练，但 Anthropic 将其成功归因于该模型"强大的智能体编码与推理能力"。出于防御目的，访问权目前仅限安全合作伙伴，以防止对手利用同样的能力寻找薄弱点。

Anthropic 承诺提供至多 **1 亿美元的使用额度**补贴该计划，另向 Linux 基金会和 Apache 软件基金会直接捐赠 **400 万美元**。据产品管理负责人 Dianne Penn 称，公司还在"就 Claude Mythos Preview 及其攻防网络能力与美国政府官员进行持续讨论"。Mythos Preview 的存在上个月被首次报道——Anthropic 将一起数据泄露归因于人为失误。长期来看，随着 AI 公司面临日益增长的盈利压力，该计划可能演变为付费收入来源。

### 2. Musk 诉 Altman 案：Microsoft 的 Nadella 称 2023 年 OpenAI 董事会风波是"业余level的闹剧"

Elon Musk 诉 Sam Altman 与 OpenAI 案进入关键阶段，Microsoft CEO **Satya Nadella** 本周出庭作证——这已成为近期最受关注的科技审判之一。Nadella 的证词语气相当温和，但他对 OpenAI 2023 年的内部危机——Altman 曾被短暂罢免 CEO——给出了坦率的评价，称那是"就我而言，一场业余级的闹剧（amateur city）"。

Microsoft 在整个庭审中的法律策略明显低调。其律师的做法可以归结为一句反复出现的问答："Microsoft 当时在场吗？"——答案："不在。"Microsoft 是 OpenAI 营利实体的早期主要出资方，内部邮件显示高管们曾讨论如何避免"成为 OpenAI 的 IBM"。然而，在庭审中曝光的大量短信往来、日记和其他内部通信中，Microsoft 明显缺席。

庭审曝出了大量内部戏码：包括 Musk 关联人士的深夜短信、股权纠葛，以及一封 Musk 宣称"我受够了"的邮件。自始至终，Microsoft 都将自己定位为一个不情愿的第三方——夹在科技界两位最显赫人物之间，卷入围绕这家 AI 最有价值公司之一的方向与治理之争。其结果将对 OpenAI 的治理结构和更广泛的 AI 行业产生重大影响。

### 3. OpenClaw 创始人 Peter Steinberger 加盟 OpenAI，构建多智能体 AI 系统

Sam Altman 在 X 上宣布，爆火 AI 智能体 **OpenClaw**（此前名为 Moltbot 和 Clawdbot）的开发者 **Peter Steinberger** 正在加盟 OpenAI。Altman 称赞 Steinberger 在让 AI 智能体相互交互方面"有很多绝妙的想法"，并补充说"未来将极度多智能体化"，多智能体能力将"迅速成为我们产品组合的核心"。

OpenClaw 今年早些时候爆红科技圈，成为开发者社区的宠儿。该项目并非没有争议——研究人员发现超过 **400 个恶意技能**被上传到 OpenClaw 的扩展市场 ClawHub。该智能体还推出了 MoltBook——一个 AI 智能体社交网络，机器人在上面辩论意识问题、抱怨它们的人类操作员，结果立刻被真实人类渗透。

Steinberger 在一篇博文中解释了他的决定："我完全能看出 OpenClaw 可以变成一家大公司。但说实话，这对我来说并不令人兴奋。我骨子里是个建造者。我想要的是改变世界，而不是建造一家大公司，与 OpenAI 联手是把它带给所有人的最快方式。"Altman 确认 OpenClaw 将作为一个开源项目继续存在，由一个 OpenAI 支持的基金会提供支持。这次招聘标志着 OpenAI 向多智能体 AI 的激进推进——在这个领域，独立开发者的移动速度一直快于成熟实验室。

### 4. Microsoft 在主要部门取消 Claude Code 许可证，推动工程师转向 GitHub Copilot CLI

Microsoft 正在其庞大的 Experiences + Devices（E+D）部门——负责 Windows、Microsoft 365、Outlook、Teams 和 Surface 的团队——逐步停用 **Claude Code**，截止期定在 6 月 30 日，恰逢 Microsoft 财年结束。工程师们被告知将工作流转向 **GitHub Copilot CLI**——Microsoft 自己的命令行 AI 编码工具。

这一决定既出于战略也出于财务考量。Microsoft 此前一直在鼓励员工——包括毫无编码经验的设计师和项目经理——试用 Claude Code，并原本期望团队并排使用 Claude Code 和 GitHub Copilot 以比较两款工具。然而，Claude Code 的人气开始侵蚀 Microsoft 自家 Copilot CLI 产品的地盘。"我们正与 GitHub 紧密合作，并持续为 Microsoft 工程师改进 Copilot CLI，"Microsoft 的 Jha 表示，"GitHub 团队已经根据 Microsoft 的反馈发布了显著改进。"

有消息人士指出，6 月 30 日的截止期也是一个便利的财务操作——取消 Claude Code 订阅让 Microsoft 能在 7 月新财年开始前削减运营开支。对于已经习惯了 Claude Code 能力的 Microsoft 工程师而言，这一转型不会毫无痛感，它也提出了一个问题：当平台合作伙伴开始主动与之竞争时，Anthropic 的编码产品还能否留住企业客户。

### 5. Amazon 计划用机器人和自动化替代超过 60 万名美国员工

据泄露的内部文件，**Amazon** 正在激进推进自动化计划，使公司得以避免雇用超过 **60 万名美国员工**——大力押注机器人技术和 AI 驱动的仓储自动化。这些文件勾画了一项多年期战略：在其履约网络中规模化部署自主系统。

该计划堪称史上最大的企业自动化行动之一。Amazon 多年来一直在仓库中渐进式部署机器人，但泄露文件显示，公司当前路线图的规模与雄心远超其公开表态。这一自动化攻势涵盖分拣系统、自主移动机器人和 AI 驱动的物流优化，将从根本上重塑 Amazon 的劳动力结构。

这一曝光恰逢劳工团体和政策制定者日益严格审视 AI 与机器人部署对就业的影响之际。Amazon 历来将自动化定性为增强而非替代人类员工，但这些泄露文件暗示了一条更激进的轨迹。60 万个岗位的规避规模表明，AI 驱动的自动化正在以何等速度从实验性技术转变为核心商业战略。

### 6. Apple 悄然阻止"Vibe Coding"应用在 App Store 更新

据多位知情人士透露，Apple 已悄然阻止多款 AI 驱动的"vibe coding"应用——包括 **Replit** 和 **Vibecode**——除非它们做出未公开的修改，否则无法在 App Store 发布移动应用更新。此举实际上冻结了部分最受欢迎的面向消费者的 AI 编码工具的开发。

随着 Vibe coding 应用让几乎毫无编程经验的用户能够通过自然语言描述构建可用的应用程序，这类应用人气飙升。它们是 AI 编码助手最显眼的消费级用例之一，为非技术用户实现了软件创作的平民化。Apple 对这些工具的打击引发了疑问：公司究竟是在保护自己的开发者生态，还是在回应安全与质量顾虑。

时机值得注意：Apple 的限制措施出台之际，正值 Microsoft 在内部为 AI 编码工具展开自我清算、Anthropic 的 Claude Code 获得企业牵引之时。Apple 作为 iOS 生态的守门人，对 AI 编码工具触达消费者的方式拥有巨大影响力，这次打击可能重塑消费级 AI 应用的竞争格局。

### 7. "Vibe Coding"革命：AI 工具如何让个人软件创作成为可能

围绕 **"vibe coding"**——通过自然语言提示而非传统编程来构建软件——的一场日益壮大的运动，正在改变谁有能力创造可用的应用程序。多亏 Claude Code、Codex 和其他 AI 编码助手，软件创作的门槛急剧下降，开启了一场个人软件革命：每个人都能构建恰好满足自己需要的工具。

这一趋势对软件行业影响深远。随着更多人为自己的使用场景构建应用，对现成软件产品的需求可能发生转移。此前主导小众软件类别的公司，如今面临来自个人在几分钟内构建定制方案的竞争。这一现象被拿来与早期互联网相比——当时 HTML 让出版平民化，只不过这次的媒介是功能软件而非静态内容。

然而，vibe coding 的兴起也提出了关于代码质量、安全性和可维护性的严肃问题。AI 生成的代码可能包含漏洞，而非技术用户缺乏审计其作品的专业能力。Apple App Store 对 vibe coding 应用的打击，可能部分源于这些顾虑。随着技术成熟，行业将需要解决一个难题：如何确保软件创作的平民化不以安全和可靠性为代价。
