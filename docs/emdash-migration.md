# EmDash migration: isolated preview and cutover

The first deployment target is the Worker `cinagroup-emdash-preview` on its `workers.dev` URL. The checked-in `wrangler.jsonc` has no custom-domain route. `.github/workflows/emdash-preview.yml` validates pushes to the isolated `codex/emdash-migration` branch without credentials or deployment; manual `workflow_dispatch` from that branch offers a read-only `audit`, `provision` for missing isolated D1/R2 resources, `migrate-contact` for the exact preview contact D1, `audit-turnstile` and `configure-turnstile` for the exact preview hostname, and an explicitly selected `deploy` operation. It must never attach `cinagroup.com` or deploy the existing `cinagroup` Pages project. **Do not merge this migration branch to the default branch:** the existing Pages workflow deploys on a `main` push, while this branch changes the site build and Cloudflare configuration. The Pages site remains the production baseline until a separate, reviewed cutover.

Provision and inspect resources in the Cloudflare account before a remote write; do not rely on automatic D1/R2 creation. The manual `audit` workflow queries exact preview resource names and checks whether a same-named Worker already exists. The manual `provision` operation creates only missing isolated EmDash D1 and R2 resources; it does not deploy a Worker. Commit the resulting EmDash D1 ID to `wrangler.jsonc` and rerun the audit. The separate `migrate-contact` operation requires the contact D1's exact name and ID, the tracked 0001 schema and indexes, and migration history containing only 0001; it then applies 0002 with Wrangler's remote D1 migration command and rechecks the Chinese locale. This preview database remains separate from `cinagroup-contact-submissions`. After the first Worker deployment, set `EMDASH_PREVIEW_ADMIN_PASSWORD` with `wrangler secret put EMDASH_PREVIEW_ADMIN_PASSWORD --name cinagroup-emdash-preview` before visiting the setup wizard; admin paths remain closed until this secret is configured. Add the encryption key with `wrangler secret put EMDASH_ENCRYPTION_KEY --name cinagroup-emdash-preview`; keep the key with the preview D1 backup so encrypted plugin settings remain recoverable. Configure Turnstile's Worker secrets through the dedicated manual operation below. Set other Worker secrets in the same named Worker, never in `wrangler.jsonc` or GitHub logs.

For the contact form, run the manual `audit-turnstile` operation first. `configure-turnstile` creates at most one managed widget named `cinagroup-emdash-preview-contact` with only `cinagroup-emdash-preview.cinagroup.workers.dev` in its domain list, or reuses that exact widget. It binds its secret and the exact hostname to the preview Worker in one Wrangler secret update, without printing the secret. `wrangler secret bulk` immediately deploys a new Worker version; the operation then rechecks route isolation and live noindex/admin responses before reporting success. The public site key appears in the workflow summary; set GitHub Actions variable `EMDASH_PREVIEW_TURNSTILE_SITE_KEY` to that value, then dispatch `deploy` again so the form embeds the matching widget. Repeating `configure-turnstile` reuses the widget and refreshes both Worker secrets, which also repairs a rotated widget secret. If the token lacks `Turnstile Sites Read`/`Write` or `Workers Scripts Write`, the operation fails with an HTTP status/code or sanitized Wrangler exit status; a widget created before a Worker-secret failure is reused on retry. The read-only audit does not fetch the widget secret or change Cloudflare state. A preexisting same-name widget with any extra domain or different mode is rejected.

The preview URL is public unless access controls are configured. This Worker serves only the exact `cinagroup-emdash-preview.cinagroup.workers.dev` hostname and returns 421 for any other public hostname, including an accidental custom-domain attachment. It allows only Astro Cloudflare adapter build-time requests to `http://localhost:<port>/__astro_*` internal endpoints; these do not authorize other public hosts. It gates all `/_emdash` requests before EmDash sees any admin or setup request. Configure `EMDASH_PREVIEW_ADMIN_PASSWORD` as a preview Worker secret with a random 32+ character value, then open `/_emdash/admin/` and sign in to the HTTP Basic prompt with username `preview` and that password. The Worker issues an eight-hour, `HttpOnly; Secure; SameSite=Strict` cookie for the setup wizard's API calls; rotating the secret invalidates issued cookies. This outer gate protects the first-admin setup and remains in place afterward. It does not hide the public preview site or replace EmDash's own admin login. The preview Worker adds `X-Robots-Tag: noindex, nofollow` to every response, including hostname rejections. Its `assets.run_worker_first` setting sends prerendered HTML and static assets through that Worker too; verify the header on old static pages, assets, API routes, and CMS pages before sharing the URL. Check that neither the preview Worker in the Cloudflare dashboard nor the generated Wrangler deployment configuration has a custom-domain route, especially `cinagroup.com`. The preview cron in `wrangler.jsonc` runs against isolated preview bindings; confirm scheduled tasks cannot call production services.

EmDash reads `seed/seed.json` into the bundle and applies its content model only when the new database is empty and setup has not completed. This checked-in seed has no article content; the separately generated pilot draft seed is a review artifact. Later schema changes or draft imports need an explicit, reviewed operation against the preview database. The public CMS bridge currently serves en/zh/ja, where public blog indexes exist. Before publishing CMS posts in ko/ru/es/pt/fr, add matching blog indexes and extend the public locale allowlist; otherwise those languages remain available only as private drafts/previews.

Inspect the generated Wrangler deployment target before any upload. This check must pass on the exact build output that will be deployed:

```sh
node --input-type=module <<'NODE'
import { readFileSync } from 'node:fs';
import { dirname, resolve } from 'node:path';
const pointerPath = resolve('.wrangler/deploy/config.json');
const pointer = JSON.parse(readFileSync(pointerPath, 'utf8'));
const config = JSON.parse(readFileSync(resolve(dirname(pointerPath), pointer.configPath), 'utf8'));
const db = (binding) => config.d1_databases?.find((item) => item.binding === binding);
const media = config.r2_buckets?.find((item) => item.binding === 'MEDIA');
const session = config.kv_namespaces?.find((item) => item.binding === 'SESSION');
if (config.name !== 'cinagroup-emdash-preview' || config.route || config.routes?.length || config.domains?.length || config.workers_dev === false) throw new Error('Unsafe preview Worker target');
if (config.assets?.run_worker_first !== true) throw new Error('Static assets bypass the noindex Worker');
if (db('DB')?.database_name !== 'cinagroup-emdash-preview') throw new Error('Unexpected EmDash D1 binding');
if (db('CONTACT_DB')?.database_name !== 'cinagroup-contact-submissions-preview' || db('CONTACT_DB')?.database_id !== 'a24a999d-f784-4ee1-8dcd-888a7be43e7c') throw new Error('Unexpected contact D1 binding');
if (media?.bucket_name !== 'cinagroup-emdash-media-preview') throw new Error('Unexpected media bucket');
if (!session || config.images?.binding !== 'IMAGES') throw new Error('Missing Astro session or images binding');
console.log('Isolated preview target verified');
NODE
npx wrangler deploy --dry-run --name cinagroup-emdash-preview
npx wrangler check startup --outfile /tmp/emdash-startup.cpuprofile
```

## Cutover gate and rollback

Before scheduling cutover, finish the preview checks, resolve the contact hostname gate, and prove that an approved EmDash post appears on its public `/blog/{slug}/` route, list, RSS, and sitemap while a draft stays private. The temporary `/cms-preview/{slug}/` route remains for signed draft previews; align EmDash's published View links with the public routes. Take recoverable snapshots of EmDash D1, contact D1, R2 media, and the encryption key. Record the known-good Pages deployment and DNS/domain settings. Freeze editorial writes while reconciling content and media; verify production-specific D1/R2 bindings and secrets in a separately reviewed Worker configuration. Attach `cinagroup.com` only in a separate production change after the gate passes. Then recheck representative URLs, robots/canonical/hreflang, sitemap/RSS, admin permissions, media, and a real contact submission on the live domain.

For a bad preview release, restore its previous Worker deployment and keep the preview resources for diagnosis. For a failed production cutover, route `cinagroup.com` back to the recorded Pages deployment and verify the same routes and contact flow. Preserve EmDash D1/R2 and the encryption key; reconcile writes made during the cutover window before another attempt. Restoring a Worker bundle alone does not roll back D1 or R2 data.
