# EmDash migration: isolated preview and cutover

The first deployment target is the isolated Worker `cinagroup-emdash-preview` on its `workers.dev` URL. The checked-in `wrangler.jsonc` has no custom-domain route. The migration workflow validates pushes to `codex/emdash-migration` without deployment; manual dispatch separates read-only audits, isolated resource setup, Access application setup, runtime-binding setup, and the explicit `deploy` operation. Follow [the CinaAuth → Access runbook](emdash-cinaauth-access.md) for the new admin path. The old password/passkey gate is [legacy rollback context](#legacy-password-and-passkey-rollback-reference), not a setup step for the current branch. **Do not merge this migration branch to the default branch:** a `main` push still runs the Pages workflow. The Pages site remains the production baseline until a separate, reviewed cutover. The live Pages `robots.txt` advertises `sitemap-index.xml` although the checked-in static asset does not; the Worker retains that live discovery entry and adds the CMS sitemap only after a discoverable article exists.

Provision and inspect resources in the Cloudflare account before a remote write; do not rely on automatic D1/R2 creation. The manual `audit` checks exact preview resource names and same-named Worker existence. `provision` creates only missing isolated EmDash D1/R2 resources; it does not deploy code. Commit the resulting EmDash D1 ID to `wrangler.jsonc` and rerun the audit. The separate `migrate-contact` operation requires the exact contact D1 name and ID, tracked 0001 schema and indexes, and migration history containing only 0001; it applies 0002 to that preview D1 and rechecks Chinese locale. The preview database remains separate from `cinagroup-contact-submissions`. For admin authentication, run `audit-access`, `configure-access`, and `configure-access-runtime` in order, with review between steps; these operations verify or set up the dedicated preview Access applications and six absent Worker bindings but do not upload the new Worker code. Then use explicit `deploy` and verify live behavior. Use `audit-secrets`/`configure-encryption` for an absent encryption key and preserve it with preview D1 backups. Set other secrets on this named Worker only.

For the contact form, run the manual `audit-turnstile` operation first. `configure-turnstile` creates at most one managed widget named `cinagroup-emdash-preview-contact` with only `cinagroup-emdash-preview.cinagroup.workers.dev` in its domain list, or reuses that exact widget. It binds its secret and the exact hostname to the preview Worker in one Wrangler secret update, without printing the secret. `wrangler secret bulk` immediately deploys a new Worker version; the operation then rechecks route isolation and live noindex/admin responses before reporting success. The public site key appears in the workflow summary; set GitHub Actions variable `EMDASH_PREVIEW_TURNSTILE_SITE_KEY` to that value, then dispatch `deploy` again so the form embeds the matching widget. Repeating `configure-turnstile` reuses the widget and refreshes both Worker secrets, which also repairs a rotated widget secret. If the token lacks `Turnstile Sites Read`/`Write` or `Workers Scripts Write`, the operation fails with an HTTP status/code or sanitized Wrangler exit status; a widget created before a Worker-secret failure is reused on retry. The read-only audit does not fetch the widget secret or change Cloudflare state. A preexisting same-name widget with any extra domain or different mode is rejected.

The preview public site remains anonymously readable, while the current branch guards `/_emdash` with verified Cloudflare Access identity and fails closed when its required runtime bindings are missing. Access protects the preview host's `/_emdash` path and descendants; its narrower public-file-media application allows only canonical GET/HEAD `/_emdash/api/media/file/<key>` reads. There is no password form, Basic fallback, or cookie-based pilot bypass in the current branch. The Worker also enforces the exact `cinagroup-emdash-preview.cinagroup.workers.dev` hostname and returns 421 for other public hostnames, including an accidental custom-domain attachment. Only Astro Cloudflare adapter build-time requests to `http://localhost:<port>/__astro_*` are allowed internally. The preview Worker adds `X-Robots-Tag: noindex, nofollow` to every response, including hostname rejections. Its `assets.run_worker_first` setting sends prerendered HTML and static assets through the Worker. Verify the header on old static pages, assets, API routes, and CMS pages, and check that neither Cloudflare nor generated Wrangler configuration attaches a custom-domain route, especially `cinagroup.com`. The preview cron uses isolated bindings; confirm scheduled tasks cannot call production services.

The generated static sitemap index and numeric shards are served through ASSETS before Astro so EmDash native collection sitemap routes cannot shadow them. Their original request, query, conditional headers, status, and XML bytes are preserved.

The preview sets Astro `trailingSlash` to `ignore` so native EmDash admin/API URLs match without rewriting request URLs, methods, bodies, or authentication headers. Directory build output and `SITE.trailingSlash: true` preserve public canonical URLs. Legacy static canonical redirects still run before Astro; successful public CMS HTML GET/HEAD responses on known blog routes redirect with 308 to their trailing-slash URL, preserving query parameters. Missing, error, and non-HTML responses retain their statuses.

The current branch has no first-admin password/passkey setup procedure. CinaAuth login must first satisfy the dedicated Cloudflare Access application and the Worker guard, and EmDash administrator provisioning still needs live verification. Access application and runtime configuration do not create an EmDash admin user. Historical password/passkey instructions are retained only under [legacy rollback](#legacy-password-and-passkey-rollback-reference).

For encryption, run `audit-secrets` first. If the Worker has no key, generate 32 cryptographically random bytes, encode canonical unpadded base64url, prefix with `emdash_enc_v1_`, and store the result securely as GitHub secret `EMDASH_ENCRYPTION_KEY` before `configure-encryption` or `deploy`. Code deployment prepares an absent key with the same guarded operation. Back it up with preview D1; the local migration backup is DPAPI-encrypted for the Windows account and excluded from Git. The operation checks exact bindings, hostname, routes, and domains before writing, preserves other secret names, and verifies live noindex/admin behavior afterward. An existing key is not rotated: old ciphertext needs the original key.

The public-file-media exception is narrow: anonymous GET/HEAD is allowed only for canonical `/_emdash/api/media/file/<key>` URLs, including once-encoded Unicode and spaces. Private backup/transfer prefixes, noncanonical or ambiguous keys, upload/metadata APIs, and other `/_emdash` paths remain protected. EmDash's own public-file guard still applies. Its `siteUrl` is the exact preview origin for authentication callbacks; public article canonical metadata continues to use `cinagroup.com`.

EmDash reads `seed/seed.json` into the bundle and applies its content model only when the new database is empty and setup has not completed. The checked-in seed has no articles; the generated pilot draft seed remains a review artifact. The earlier REST/PAT import script depended on the legacy password cookie and cannot run against the new Access guard. Design Access Service Auth plus EmDash PAT handling and idempotent preview-only imports separately before a remote import. The public CMS bridge serves all eight locales: en/zh/ja retain static archives and add approved CMS posts; ko/ru/es/pt/fr use CMS-only indexes. Empty native indexes are noindex, and database/pagination failures return 503 without a partial list. A route's existence does not assert a translation. Signed `/cms-preview/` pages and `/_emdash` paths stay out of the public sitemap.

Inspect the generated Wrangler deployment target before any upload. This check must pass on the exact build output that will be deployed:

```sh
node --input-type=module <<'NODE'
import { readFileSync } from 'node:fs';
import { dirname, resolve } from 'node:path';
const pointerPath = resolve('.wrangler/deploy/config.json');
const pointer = JSON.parse(readFileSync(pointerPath, 'utf8'));
const config = JSON.parse(readFileSync(resolve(dirname(pointerPath), pointer.configPath), 'utf8'));
const db = (binding) => config.d1_databases?.find((item) => item.binding === binding);
const media = config.r2_buckets?.find((item) => item.binding === 'MEDIA');
const session = config.kv_namespaces?.find((item) => item.binding === 'SESSION');
if (config.name !== 'cinagroup-emdash-preview' || config.route || config.routes?.length || config.domains?.length || config.workers_dev === false) throw new Error('Unsafe preview Worker target');
if (config.assets?.run_worker_first !== true) throw new Error('Static assets bypass the noindex Worker');
if (db('DB')?.database_name !== 'cinagroup-emdash-preview') throw new Error('Unexpected EmDash D1 binding');
if (db('CONTACT_DB')?.database_name !== 'cinagroup-contact-submissions-preview' || db('CONTACT_DB')?.database_id !== 'a24a999d-f784-4ee1-8dcd-888a7be43e7c') throw new Error('Unexpected contact D1 binding');
if (media?.bucket_name !== 'cinagroup-emdash-media-preview') throw new Error('Unexpected media bucket');
if (!session || config.images?.binding !== 'IMAGES') throw new Error('Missing Astro session or images binding');
console.log('Isolated preview target verified');
NODE
npx wrangler deploy --dry-run --name cinagroup-emdash-preview
npx wrangler check startup --outfile /tmp/emdash-startup.cpuprofile
```

## Cutover gate and rollback

Before scheduling cutover, finish the preview checks, verify the Access policy and Worker guard with anonymous and selected-account requests, resolve the contact hostname gate, and prove that an approved EmDash post appears on its public blog route, list, RSS, and sitemap while a draft stays private. Align published View links with public routes while retaining signed draft previews. Take recoverable snapshots of EmDash D1, contact D1, R2 media, and the encryption key. Record the known-good Pages deployment and DNS/domain settings. Freeze editorial writes while reconciling content and media; verify production-specific D1/R2 bindings, Access application, and Worker runtime configuration in a separate reviewed change. Attach `cinagroup.com` only after the gate passes. Then recheck representative URLs, robots/canonical/hreflang, sitemap/RSS, admin permissions, media, and a real contact submission on the live domain.

For a bad preview release, restore its previous Worker deployment and keep the preview resources for diagnosis. For a failed production cutover, route `cinagroup.com` back to the recorded Pages deployment and verify the same routes and contact flow. Preserve EmDash D1/R2 and the encryption key; reconcile writes made during the cutover window before another attempt. Restoring a Worker bundle alone does not roll back D1 or R2 data.

## Legacy password and passkey rollback reference

The baseline preview Worker used `EMDASH_PREVIEW_ADMIN_PASSWORD`, an eight-hour signed cookie or HTTP Basic challenge, and the native first-user passkey wizard. Workflow run 36662548088 configured that password, and anonymous native admin returned 401. These observations describe the **pre-Access Worker only**. They are useful when restoring that exact previous Worker deployment for diagnosis; do not run `configure-admin-password`, reuse its cookie, or follow the wizard instructions on the current branch. Restore only with the corresponding old code and secret inventory, and verify the public-site/noindex boundary afterward. The [CinaAuth → Access runbook](emdash-cinaauth-access.md) is authoritative for the new path.
